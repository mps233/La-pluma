# MAA 6.20 覆盖矩阵审计

> 审计对象：MaaCore 6.20.1 / maa-cli 0.7.7 的参数、回调、任务类型与 Agent API 覆盖。
> 方法：4 个只读审计域并行比对 MAA 6.20 协议文档与当前代码，再由独立复核代理逐行校验。
> 状态定义：**已对齐** = 相关路径都能暴露并传给 MaaCore；**部分对齐** = 仅单一路径生效、丢失行为或存在协议偏差；**缺失** = 未实现；**不适用** = 内部/协议事件无用户价值；**GUI-only** / **CLI 不支持** = 当前 CLI 无法表达。

## 关键项目侧差距（按优先级）

### P0：参数键/必填语义错误（审计后已修复）

1. **`find_playTime_target` 键名写错**
   - 项目写入并校验的是 `find_play_time_target`，MAA 6.20 实际字段是 `find_playTime_target`。
   - 审计后已统一改为 `find_playTime_target`，并在模式 20001 未选择时默认节点 1。
   - 位置：`client/src/components/RoguelikeTasks.tsx` 的 `numberFields` 与模式 20001 校验。

2. **BlackFlow 30003 的 `blackflow_start_animals` 空数组未发送**
   - MAA 要求 mode 30003 必填该字段，空数组表示准备局只进第三层、不培育动物。
   - 审计后已改为 mode 30003 始终发送数组，并校验最多 2 项、羽蛇最多 1 项。
   - 位置：`RoguelikeTasks.tsx` 的 `listFields` 映射。

3. **恢复执行路径的多关卡 Fight 仍拼成单个 `stage:times` token**
   - `AutomationTasks.tsx` 的恢复 builder 把多个关卡拼成 `1-7:3,CE-6` 交给 `run-task`，`maa fight` 不解析逗号，和调度器逐关执行路径不一致。
   - 审计后已抽出 `buildDynamicFightCommand`：多关卡自动生成一个包含多个 `Fight` 子任务的动态配置，单关卡且无新参数仍走 CLI；已补单测。
   - 仍建议动态 Fight 构建前调用 `replaceActivityCode`。

### P1：公开参数/回调缺口

- **Recruit**：已补 `report_to_penguin`、`penguin_id`、`report_to_yituliu`、`yituliu_id`、`server` 控件。
- **Fight `/actions/fight`**：已补 `medicineExpireDays`、`server`、`drops`、上报参数、`DrGrandet`、`clientType`，并在需要时走动态 Fight。
- **StartUp**：`start_game_enabled` 无控件；`account_name` 只在自动化表单，未进入 `/actions/start-game` 契约。
- **Roguelike**：缺少 `collectible_mode_core_char_list`（模式 30003 准备局开局干员，未提供时回退主列表）；`find_playTime_target` 见 P0。
- **Copilot**：原生委托已补 `--use-sanity-potion`、`--formation`、`--formation-index`、`--add-trust`、`--ignore-requirements`、`--support-unit-usage`、`--support-unit-name`，并对 CLI 无法表达的组合回退动态计划；`user_additional` 已补文本输入、解析和原生委托回退。
- **ParadoxCopilot**：多作业没有对象 `{id, filename}` 的 `list` 入口，也没有按作业跟踪加载结果。
- **Custom**：白名单只覆盖 5 个工具；通用 `run-task` 可传任意 Custom params，但 UI 没有 SecretFront 等入口。保持白名单策略即可，除非要暴露 SecretFront。

### P1：新增回调未解析/未展示

- `BlackFlowStartRun`、`BlackFlowScrapTradeAborted`、`CopilotPrecheckFile`、`StageInfo`、`StageInfoError`、`UnsupportedLevel`、`RecruitSpecialTag`、`RecruitTagsSelected`：已由 `summarizeAuxiliaryCallbacks` 解析，并通过 `GET /api/agent/logs/maa-callbacks` 暴露。
- 连接/性能事件（`ConnectFailed`、`Reconnecting`、`ScreencapFailed`、`TouchModeNotAvailable`、`ResolutionChanged`、`ScreencapCost`、`EmulatorFPS` 等）：目前多数未进入项目状态；属于诊断增强，不影响任务参数对齐。

### P2：Agent API / 契约

- `run_task` 命令白名单、动态 `taskConfig.tasks`、任务类型校验存在“协议可表达但语义动作未覆盖”的差异；多数属于预期，但需要用契约测试固定。
- `SwitchTheme` 为 MAA GUI/Core 能力，maa-cli 0.7.7 不支持，保持不暴露。
- `StartUp`、`Fight`、`Recruit`、`Infrast`、`Mall`、`Award`、`Roguelike`、`Copilot`、`Depot`、`OperBox`、`Reclamation`、`SingleStep`、`VideoRecognition` 在 Agent API 中均为部分覆盖；核心路径可用，但字段级契约不完整。

### 明确不处理

- GUI-only：PC Win32 连接、MuMu IPC 触控增强、DepotMaintain、UpdateData、MAA 通知、`SwitchTheme` 等。
- 6.21 beta / 0.8 nightly 的 Breaking 项。
- MAA 内部导航/确认事件（`StartButton2`、`MedicineConfirm`、`StoneConfirm`、`StageTrader*` 等）如果没有用户可见价值，不要求逐项建模。
